Here's a full summary of everything that shipped in Phase 2:

What's now live:

Backend infrastructure

POST /api/notifications/subscribe — saves each device's push token to the new push_subscriptions table
DELETE /api/notifications/subscribe — unsubscribes a device
GET /api/notifications/config — tells the frontend whether push is active and shares the public key
POST /api/notifications/send/plan-created — sends the immediate confirmation after calendar export
POST /api/notifications/send/test — sends a test ping so users can verify it's working
POST /api/notifications/send/custom — generic trigger for future leave-now / buffer-shrinking / traffic alerts
Notification templates (calm, category-aware)

✅ Plan confirmed — wake up + leave times in the body
⏰ Start getting ready — destination + leave time
🚗 Leave now — Risky plans get "cutting close" variant
⚠️ Buffer shrinking — plan name
🟢 You're on track — minutes until leave
🚗 Traffic ahead — how many extra minutes to allow
Frontend

NotificationOptIn component — appears on both the Alerts and Results pages; shows Enable / Active (with test button) / Blocked / Not configured states
Immediate push notification fires when you tap "Add to Calendar" — calendar events can't send push, so Araamu does it right at that moment
Auto-fires on first results page load if you're already subscribed (using sessionStorage to prevent duplicate sends)
Custom service worker (sw.ts) handles incoming push messages and routes notification clicks to the right plan
One thing to know about the Replit preview: service workers are blocked inside the preview iframe, so the opt-in card spins briefly then shows the Enable button. On a real device or the deployed URL, it resolves instantly and the full permission + subscription flow works end-to-end.
