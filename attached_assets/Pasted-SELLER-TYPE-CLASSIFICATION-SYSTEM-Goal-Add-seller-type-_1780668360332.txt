SELLER TYPE CLASSIFICATION SYSTEM

Goal:

Add seller_type classification to RideCheck so workflows can dynamically adapt based on who is selling the vehicle.

This should become a foundational field used throughout:

* Order creation
* Ops workflow
* Seller contact
* RideChecker workflow
* Risk Intelligence
* Report generation
* QC review

Do NOT create separate order systems.

Create one order workflow with conditional logic based on seller_type.

════════════════════════════════════
PHASE 1 — DATABASE
════════════════════════════════════

Add column to orders table:

seller_type TEXT DEFAULT 'private_party'

Allowed values:

* private_party
* dealership
* auction
* other

Add index:

CREATE INDEX idx_orders_seller_type
ON orders(seller_type);

Backfill existing records:

seller_type = 'private_party'

for all existing orders.

════════════════════════════════════
PHASE 6 — RISK INTELLIGENCE
════════════════════════════════════

Use seller_type in scoring.

Private Party:

Increase weight of:

* title issues
* lien issues
* ownership inconsistencies

Dealership:

Increase weight of:

* disclosure issues
* denied OBD scan
* denied road test

Auction:

Increase weight of:

* missing disclosures
* title uncertainty
* arbitration limitations

Other:

Use neutral weighting.
